# F3 amendment after r03 — the Palantir podcast on the stack model, 2026-09-27

**Recording:** r03, an 11-minute German podcast episode with a 28-second trailer at the start.
The transcript is third-party content and stays under gitignored `scripts/eval/local/r03/`.
The checklist is `tests/fixtures/eval/notes/assertions/r03_de_palantir_podcast.assertions.json`.
**Model:** `notes-chat` (Gemma 3 4B, Q4_K_M) through Ollama on the dev Mac, temperature 0.
**Tool:** `scripts/eval/notes_assert.py`. One run takes 10 to 13 minutes.

## Result

| Run | Engine | Checks passed |
|---|---|---|
| Scripted stand-in | the amendment as built | 17 / 17 gated |
| Stack model, run 1 | the amendment as built | 18 / 34 |
| Stack model, run 3 | + failed introductions become key points, header without bracket | 20 / 34 |
| Stack model, run 5 | + copy check without the header, unsaid-number lines dropped | 19 / 34 |

**Passing on the stack model:** the trailer is cut as an advertisement, and "Chris Hansen",
"Dateline", "Gysi" and "Präsentiert von" are absent. No "Technische Daten" table, no
"Zwanzig Jahre" or "Eine Software" figure. None of the five claims the other product invented.
Every line is cited, no bullet sits above the first heading, and paragraph 1 names the type,
the subject and three or more themes.

**Failing on the stack model:**

- **Almost every fact is a copy.** In run 5, 23 of 25 kept facts are transcript lines word for
  word. F2 stores a copy as evidence and never writes it as a line. The restate retry
  improved one window of two. With about two statements left, the topics pass fails
  (`all_bullets_unsupported`), there is too little for chapters (`chapters_min`), and no second
  paragraph can be composed (`overview.prose_paragraphs_min`). The names the checklist wants
  ("Peter Thiel", "Alex Karp", "PayPal", "Habermas", "2004", "3000") are in those copies.
- **Recording type.** The classifier says `lecture_webinar`, and the context pass calls the
  episode a sales call. The checklist wants `podcast_broadcast`.
- **Guest.** Felix Holtermann's introduction is not extracted as one, so there is no guest line.
  The person-details follow-up also overran its token budget once per run.

## What the stack model broke, and what now handles it

- **One introduction hint turned a whole window into introductions.** Told that one line of the
  second window introduces somebody, the model filed all 15 facts of that window as
  introductions. None introduced anyone, so all were dropped and the second half of the episode
  had no facts. An introduction that introduces nobody, with real words behind it, is now a key
  point (`introductions_demoted`, 14 in each run).
- **"Speaker 1 (06:47): …" without the bracket.** That header form is now stripped when it
  carries a real mm:ss. "Budget (2026): …" is left alone.
- **The copy check ran on text with the header.** A copied line with a header was written as a
  statement. It is now evidence.
- **"(fact_id:" at the end of a bullet.** The singular and cut-off forms are stripped.
- **"Fast Menschen sterben."** The text named 3000 deaths and cited the line about the second
  plane. The number was removed as never said, and the rest stayed. A line that lost a number
  and whose words the quote does not carry is now dropped. Composed prose also skips any fact
  flagged as unsupported.

## Open

- **F2 and §2.9 disagree when everything is a copy.** §2.9 says the overview is always two
  paragraphs. F2 says a transcript sentence is never a line. The engine keeps F2, so on this
  model the overview can be one paragraph. Writing composed prose from copies would satisfy
  §2.9 and break F2. This is a product decision.
- **The copy rate is the model.** Gemma 3 4B restates rarely even when asked once more. The same
  checklist on a stronger model is the test of the engine rather than the model.
- **Support thresholds are not calibrated.** en 0.5, de 0.4, uk 0.4 are the amendment's
  expected values. Calibration needs a judge stronger than the model under test on
  `eval/notes/v2`: `notes_eval.py --judge <backend> --judge-lines …`, then
  `support_calibration.py`.
- **Blind overview question.** It is on the pairs sheet and needs human raters.
- **r03 in the eval bucket.** Not uploaded from here.
