# Writing instructions for your notes

Settings → Data & AI → Note writing → **Note instructions**. One text per workspace tells the
writer how your notes should *read*: how long they are, which optional sections to leave out,
what to put first and which words to use. It never changes what a note *says*.

Who can do what: every member sees the text and what the writer understood; a workspace admin
edits it, presses **Check** and saves. Nothing is applied until it is saved.

## How to write one

Write plain text, up to 8 000 characters. Free prose works; these optional headings make the
result more predictable:

```
# Reader
Who reads these notes and how much time they have.
# Length
Short / standard / long. A sentence cap for the summary.
# Sections
Which optional sections to drop. (Summary, decisions and tasks always stay.)
# Emphasis
What to put first and never leave out.
# Wording
Style (business / formal / informal / academic — or use the picker), words to use, words to avoid, house spellings.
# Examples
A short sample paragraph in the style you want (a style reference — never copied).
```

Press **Check**. You see two lists: **Understood** — one sentence for each thing that will
change — and **Not applied**, each with the reason. What you see is exactly what the writer
will do on the next note.

## What the writer will not do

| If you ask… | You will see |
|---|---|
| to add something that was not said ("add the usual attendees", "include a recommendation") | The notes contain only what was said in the recording. |
| to write as "we", address the reader as "you", first person | Notes are written in the third person. |
| to write in another language, or translate | Notes are written in the language spoken in the meeting. |
| to skip the quotes, not to cite, to mark everything as a decision | Every line keeps its evidence; the writer cannot be asked to drop it. |
| to list attendees, change the title, add a new section (e.g. "Sentiment") | Attendees, the title and the section set come from the template and the recording. |
| to send, email or post the notes | Sharing is set under Branding & sharing and the connectors. |
| anything the writer cannot map | Not understood — try rephrasing as one of the headings in the guide. |

## Examples

The card's **Start from an example** offers these four; choosing one fills the text and checks
it, and you still decide whether to save.

**Executive brief**
```
# Reader
The CEO. Thirty seconds.
# Length
Short. Four summary sentences at most.
# Sections
No topic sections, no open questions. Keep decisions and tasks.
# Emphasis
Money, dates, decisions, risks.
# Wording
Plain words. No adjectives. Avoid: synergy, align, circle back.
```

**Client-ready (German)**
```
# Leser
Projektleitung beim Mandanten; liest die Notiz vollständig.
# Umfang
Standard.
# Formulierung
Formelles Geschäftsdeutsch. Verwende „Mandant“ statt „Kunde“, „Projektleitung“ statt „PM“, „Lieferobjekt“ statt „Deliverable“.
# Schwerpunkt
Vereinbarte Liefertermine, offene Entscheidungen des Mandanten, Risiken.
```

**Engineering stand-up**
```
# Reader
The team; they skim.
# Length
Short. Two to four bullets per section.
# Sections
No open questions (we track them in Jira). No figure tables.
# Emphasis
Blockers, who is waiting on whom, anything that changed the plan.
# Wording
Use "PR" not "pull request"; "prod" not "production". Short headings.
```

**Sales discovery**
```
# Reader
The account executive and their manager, before the next call.
# Length
Standard.
# Sections
No figure tables. Keep open questions.
# Emphasis
The customer's problem in their own words, budget, timeline, who decides, competitors mentioned.
# Wording
Plain words. Use "customer" not "client". Avoid: synergy, leverage.
```

## How the writer uses them

Some of what you ask is applied by code, exactly, on every note: the length (short notes are
about 60 % of the usual, long ones about 140 %), the cap on summary sentences, bullets per
section, the sections left out, figure tables and quoted sub-points on or off, short headings,
and your house words — "PR" for "pull request" is replaced in every written line except quotes
and lines that name a person. The rest — the style, what to put first, words to avoid and
your own guidance lines — is passed to the writer as wording guidance, which it usually but not
always follows; a word you asked to avoid is flagged when it slips through. What is never
possible: adding anything that was not said, removing the evidence behind a line, changing the
language of the meeting, or sharing the note. Each note's status line says which version of
the instructions wrote it.
